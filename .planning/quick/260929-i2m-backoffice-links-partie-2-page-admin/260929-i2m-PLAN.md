<decisions>
Locked decisions — implement these exactly, do not re-litigate.

- **D-01 Session cookie format.** Name `sr_admin`. Value `<expiryMsEpoch>.<hmacHex>` where
  `hmacHex = HMAC-SHA256(secret, String(expiryMs))`. Verify = split on the first `.`, require 2
  non-empty parts, require `Number.isSafeInteger(expiry) && expiry > Date.now()`, recompute the HMAC
  and compare. Moving the expiry forward changes the signed payload, so it is rejected.
- **D-02 Constant-time comparison.** Never `===` on a secret. Compare
  `timingSafeEqual(sha256(a), sha256(b))` — both operands are always 32 bytes, so `timingSafeEqual`
  can never throw on a length mismatch (it throws when lengths differ). Same helper for the password
  and for the HMAC hex.
- **D-03 Secret.** `ADMIN_SESSION_SECRET` if set, otherwise
  `sha256('sr-admin-session:v1:' + ADMIN_PASSWORD)`. Document in README that rotating
  `ADMIN_PASSWORD` invalidates every existing session — that is the intended behaviour.
- **D-04 Not configured = closed.** If `ADMIN_PASSWORD` is unset/empty, `adminConfigured()` is false:
  login always fails with `Back-office non configuré.`, and `isAuthenticated()` always returns false.
  No empty-password path, ever.
- **D-05 Cookie attributes.** `httpOnly: true`, `sameSite: 'lax'`, `path: '/admin'`,
  `secure: process.env.NODE_ENV === 'production'`, `maxAge: 30 * 24 * 3600`. `path: '/admin'` keeps
  the cookie off every public page; it still matches `/admin/` (trailingSlash).
- **D-06 Rate limit.** Module-level `Map<ip, { count, resetAt }>`, 10 attempts / 15 min, keyed by the
  first entry of `x-forwarded-for` (fallback `'unknown'`). Prune expired entries on every call and
  hard-cap the map at 500 keys (drop-oldest) so it cannot grow unbounded. A successful login clears
  the key. Over-limit message: `Trop de tentatives. Réessaie dans X minutes.` **It resets on every
  redeploy and is per-instance — acceptable here** (single low-traffic tool, the password is the real
  control); note this in the README.
- **D-07 One form, one action.** The editor is a single `<form>` wrapping every row. Field names are
  `label__<id>`, `sublabel__<id>`, `href__<id>`, `active__<id>`, plus one hidden `ids` input holding
  the comma-joined id order. Every button is `<button name="intent" value="…">`. So **every**
  mutation posts the complete form → reorder/add/delete can never lose in-progress typing. One
  server action `editorAction(prevState, formData)` handles all intents.
- **D-08 Persist-when-valid.** Pipeline for every intent: auth guard → parse the form into items →
  apply the structural op → `validateItems` → if valid **and** the intent mutates, derive deeplinks,
  `saveDraft(...)`, `revalidatePath('/admin')`, message `Enregistré`; if invalid, write **nothing**
  and return the items with per-field errors and `Corrige les erreurs avant d'enregistrer.` Exception:
  `add` appends a blank row and intentionally returns unsaved (a blank row cannot validate) with the
  neutral message `Nouvelle ligne — remplis label et URL, puis Enregistre.`
- **D-09 Two-step for destructive/outward actions.** `delete:<id>` and `publish` only set
  `confirm` in the returned state and re-render with a `Confirmer` / `Annuler` pair;
  `confirm-delete:<id>` and `confirm-publish` do the real work. `confirm-publish` first saves the
  draft (must validate) and then calls `publishDraft()`.
- **D-10 Preview = plain link, not `?preview=draft`.** `/links/` is an ISR route
  (`export const revalidate = 3600`). Reading `searchParams` would opt it out of static/ISR
  generation and flip it to `ƒ` in the route table, regressing part 1's guarantee for a
  once-a-month convenience. So: a `Prévisualiser /links` link with `target="_blank"` plus the note
  `montre la version en ligne, pas le brouillon`. **This is the chosen option.**
- **D-11 Derived-vs-fallback resolution.** New optional `appIos?: string | null` and
  `appAndroid?: string | null` on `LinkItem`. `undefined` = never derived (legacy row) → fall back to
  the static `APP_LINKS[href]`. `null` = derived and deliberately none. Resolution helper
  `appTargetFor(item)` lives in `lib/app-links.ts` (pure, no network):
  ```ts
  if (item.appAndroid) return { ios: item.appIos ?? null, android: item.appAndroid }
  if (item.appIos === undefined && item.appAndroid === undefined) return APP_LINKS[item.href]
  return undefined
  ```
  This guarantees today's 5 rows behave identically before *and* after a first save.
- **D-12 oEmbed is server-side, so it is stubbed by env, not by Playwright.** The brief suggested
  `context.route` — that cannot work: the oEmbed `fetch` runs inside the Next server process, which
  the browser context never sees. Instead `lib/derive-app-link.ts` reads its base URL from
  `process.env.SOUNDCLOUD_OEMBED_URL ?? 'https://soundcloud.com/oembed'`; the test run points it at a
  tiny local stub. One line, inert in production, and it makes the test fully offline and
  deterministic.
- **D-13 oEmbed never blocks a save.** 5 s `AbortSignal.timeout`, `cache: 'no-store'`, any
  failure/non-match → `appIos: null` and the returned `note` surfaces as a discreet
  `deeplink SoundCloud non résolu` line in the editor. The save still happens.
- **D-14 Re-derive only when needed.** In the save pipeline, keep the stored `appIos`/`appAndroid`
  when the href is unchanged **and** both fields are already present; otherwise re-derive. Prevents
  an oEmbed round-trip on every unrelated reorder.
- **D-15 Relative timestamps are client-only.** `il y a X` computed on the server and on the client
  disagree → hydration mismatch. Compute it in a `useEffect` + `useState` (initial `''`). Treat the
  epoch-0 seed timestamp (`1970-01-01T00:00:00.000Z`) as `jamais publié`.
- **D-16 Blob draft access level stays `public`.** Part 1's follow-up (switch `links/draft.json` to
  `access: 'private'`) is **out of scope**: still untestable locally without a token, and the draft
  holds nothing but labels and public URLs. Re-record it as a follow-up in the SUMMARY.
</decisions>
